## 约定（协作规则）

1. **一份变更请求只面向一个会话。** 硬件/固件会话与 PC 会话互相看不到对方的上下文；
   跨端的活拆成两份，各自自包含（头部都标了「面向」）。
2. **改动留在工作区，由助手审阅后分组提交。** 提交按变更请求分组，提交信息写明对应哪一份。
   这样助手能看到实际改了什么，也便于规划下一步。**别让编码工具自行提交**。
3. **文档是唯一的交接媒介。** 讨论过的结论要落纸——没落纸的等于没发生。
4. **跨端契约写在 `protocol.md` / `ui-spec.md`，不写在变更请求里。**
   变更请求是工单，会过时；契约是长期文件，两端都要照它做。
5. **改了坐标/取值要三处同步**：`ui.c`、`tools/render-*.ps1`、PC 端预览。

---

6. **硬件技术断言必须带依据。**
   写“某脚应接 3.3V”这种话，后面要跟上手手册第几页。
   查不到依据的，明写“无依据”，不要凭印象补一个说法。
   （2026-10-01 的文档复核发现，出错的断言全部是“当初写得很肯定、但没写出来处”的那类。）

7. **同一个事实只在一处维护。**
   引脚定义、元件值、时序参数这类东西，只在一份文档里写全，别处引用它，不要各拄一遍。
   拄一遍就多一个走样的机会。
   （实例：BS1 接错电平那条曾在三份文档里各有一份，改的时候差点只改一处。）

8. **改了一个事实，就全仓搜一遍这个关键词。**
   尤其是引脚名、寄存器名、元件位号这种短字符串。

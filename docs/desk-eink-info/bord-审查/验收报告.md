## 二、每处差异的判定

### 2.1 修对了的

- **C6 改对地（待修清单第 2 条，灾难级）。** 基线里 `$1N171 = {U3-13(IN), C6-2}`，VBUS 到充电 IC 输入的唯一通路是一颗电容。当前 `VBUS+ = {U3-13, C6-1, C7-2, USB1-A4, USB1-A9}`，`C6-2 ∈ GND`。VBUS 已直连 IN，C6 变成对地电容。**这是真修好了。**
- **MCP3021 VDD 改 3.3V（待修清单第 4 条）。** `U2-1(VDD)` 从 `VBUS+` 挪到 `3V3`。**修好了。**
- **I2C 上拉 10K -> 4.7K（待修清单第 7 条）。** `R6`、`R7` 的值都改成了 4.7K，R6/R7 的 1 脚都还在 3V3 上。**改对了。**
- **旧编码器上拉清理。** 删掉 `R13`/`R14`，GPIO9/GPIO10 现在真的空出来，和 `gpio-map.md` 里"已释放"的说法一致（文档说释放，网表原来是挂着 10K 上拉的，现在才真释放）。
- **R3 从 10K 改成 1K，值本身对了**（`power-arch.md` 第 83、129 行要求 1kΩ）。但**回路接法没动**，见 2.3。

### 2.2 只修了一半的

- **I2C 总线与墨水屏 SPI 短接（待修清单第 1 条，灾难级）：SCL 拆开了，SDA 还短着。**

  当前网表：

  ```
  [SCL] (4)
    U2-5(MCP3021 SCL)  U1-5(IO6)  R7-2  U4-8(DS3231 SCL)
  [GPIO18] (3)
    FPC1-13(EINK SCL)  U1-13(IO18)  R16-2
  [GPIO19] (7)
    FPC1-14(EINK SDA)  U2-4(MCP3021 SDA)  U1-14(IO19)  U1-4(IO5)
    R6-2  U4-7(DS3231 SDA)  R15-2
  ```

  `SCL` 已经是独立网络，`IO6` 和 `IO18` 分开，这一半修对了。但 **`GPIO19` 里 `U1-4(IO5)` 和 `U1-14(IO19)` 还在同一个网络上**，也就是 I2C 的 SDA（IO5）和墨水屏 SPI 的 SDA/MOSI（IO19）仍然短接，中间只隔着网络标号。基线第二轮审查 B1 条原文写的就是 `GPIO18 = {..., U1-5(IO6), ...}` 和 `GPIO19 = {..., U1-4(IO5), ...}` 两处都短，待修清单正文只摘了 SCL 那一处，用户可能就照正文只修了 SCL。**这是本次验收最重要的发现：灾难级问题只解决了 SCL 一侧，SDA 一侧仍然存在，板子照现在这样打样，I2C 和刷屏数据线依旧互灌。**

  `R6`（4.7K 上拉）目前挂在 `GPIO19` 这个混合网里，等 SDA 拆干净后它应落到真正的 I2C SDA 网上。

### 2.3 改了值但没改回路的

- **充电指示 LED1（待修清单第 6 条）。** 基线第二轮 A2 条：`$1N158 = {LED1-1(A), R3-2}`、`R3-1 ∈ GND`、`$1N157 = {U3-9(CHG#), LED1-2(C)}`。当前网表和基线**完全一样**，只把 `R3` 从 10K 改成 1K。也就是说：阳极仍经 R3 接 GND，阴极仍接 CHG#，LED 仍然反偏、仍然不会亮。限流值改对了，**拓扑还是错的**。

### 2.4 与我无关／只是清理的

- 删除 `R13`/`R14`：清理，无电气副作用。
- `C1` 仍留在 `FPC1-18` 那条网上：它不是新器件，只是随第 18 脚一起并入 3V3，见 2.5 的争议。

### 2.5 改了但方向存疑的

- **墨水屏 FPC 第 18 脚 VDD（待修清单第 3 条）：按 `eink-arch.md` 改成了 3.3V + 1µF，但厂商手册说这个脚只该挂电容到地、不该接 3.3V。**

  当前把 `FPC1-18` 和 `C1-1` 都并进了 `3V3`。厂商手册第 8 页（`manual-page-8.jpg`）第 18 脚写的是：

  > "VDD | C | Core logic power pin VDD can be regulated internally from VCI. A capacitor should be connected between VDD and VSS"

  类型是 `C`（电容脚），典型应用电路第 23 页（`manual-page-23.jpg`）里第 18 脚也只经一颗 `C6`(1µF) 到地。按本次交接的规则"以厂商手册为准"，**第 18 脚应该只挂 1µF 到 VSS，不应该接 3.3V**。`eink-arch.md` 第 110 行写的"3.3V + 1µF/25V -> GND"与手册冲突，按交接说明这份文档很可能是错的。

  这一条的本质是：用户按一份本身有错的文档去"修"，修成了手册不允许的样子。需要人工拍板（见第六节）。

#### 4.2.1 第 18 脚 VDD

见 2.5。手册第 9 页第 6.1 节还有一条旁证：`VCI` 绝对最大 `-0.5 ~ +6.0V`，`VIN`/`VOUT` 是 `-0.5 ~ VCI+0.5V`，即这面板的接口电平跟着 VCI=3.3V 走。把 VDD 直接并在 VCI 上，和"VDD 由 VCI 内部稳压得到"的表述是冲突的。结论：**当前接法不符合手册，`eink-arch.md` 的"3.3V + 1µF"应视为文档错误。**

#### 4.2.2 第 9 脚 BUSY

手册第 8 页标 `O`（输出），第 9 页 Note 5-4 说忙时输出高；第 23 页典型电路里 BUSY 到 MCU 之间**没有画上拉**。板上 `BUSY = {FPC1-9, U1-7(IO8)}`，确实没有上拉。问题在于它接的是 ESP32-C3 的 strapping 脚 IO8，上电/复位阶段 IO8 需要为确定电平，而面板未完全上电时 BUSY 是高阻。**手册没画上拉是事实，接 strapping 脚是事实**；是否必须补上拉取决于面板上电时序和 IO8 是否有内部弱上拉，这一条我标"需确认"，见第六节。

### 4.3 升压电路的元件值

手册第 23 页典型电路给出的外部升压元件（表里 Part Name / Value / Reference / Requirements）：

| 位置 | 值 | 型号/规格 |
|---|---|---|
| R1 | 2.2Ω | 0805, 1% |
| Q1 | NMOS | Si1304BDL |
| D4 D5 D6 | 二极管 | MBR0530 |
| L2 | 47µH | CDRH2D18/LDNP-470NC |
| C4 C6 | 1µF | 0603, 6V |
| C1 C2 C3 C5 C7 C8 | 1µF | 0805, 25V |
| C9 | 0.47µF | 0805, 25V |

板上实况（从 v2 全网表/BOM 读）：

- **电感：没有。** 全网表里没有任何 `L` 器件，`47µH` 无处。
- **二极管：没有。** 没有任何 `D` 器件，`MBR0530` 无处。
- **MOSFET：没有。** 没有任何 `Q` 器件，`Si1304BDL` 无处。
- **2.2Ω：没有。** 唯一的 `R1` 是 10K，挂在 `U3-1(TS)` 上（充电 IC 的热敏电阻偏置），和升压无关。
- 升压控制脚 `FPC1-2(GDR)`、`FPC1-3(RESE)` 都是单节点、悬空。
- 面板侧的储能/泵电容这一组倒是有：`VSH2=C5`、`VSH1=C2`、`VGH=C13`、`VGL=C14`、`VSL=C3` 都是 1µF，`VCOM=C4` 是 0.47µF，和手册给的电容组数值对得上；但这些是接在面板电源脚上的电容，不是升压功率级。

结论：**手册典型电路里那一整块升压功率级（L + D + Q + 2.2Ω 采样电阻）在板上完全不存在，GDR/RESE 空着。** 需要特别说明，`eink-arch.md` 第 94-95 行把 GDR、RESE 标成"悬空（内部）"，第二轮审查也据此撤回过第一轮的"漏接"判断；但厂商手册第 8 页明确 GDR 是 "N-Channel MOSFET Gate Drive Control"（对外输出）、RESE 是 "Current Sense Input for the Control Loop"（对外取样），第 23 页把它们接进外部升压级。**以厂商手册为准的话，这里缺的是一整块升压电路，属于会直接影响能否点亮的缺口。** 这条不在原待修清单里，但交接文档第 7 节第 3 项要求核对，故列出（标 C 类，见第六节）。

### 4.4 两条待定的引脚搬家

| 待定项 | 目标 | 实况 | 落地? |
|---|---|---|---|
| 墨水屏 CS# 从 GPIO4 挪到 GPIO9 | IO4 -> IO9 | `CS# = {FPC1-12, U1-3(IO4)}`；`U1-8(IO9)` 无连接 | **没落地** |
| DS3231 SQW 从 GPIO7 挪到 GPIO4 | IO7 -> IO4 | `GPIO7 = {U1-6(IO7), U4-3(SQW)}`；IO4 仍被 CS# 占着 | **没落地** |

两条都没动。可以看出来用户做了搬家前的准备（把 GPIO9/GPIO10 的上拉 R13/R14 删了，腾出 GPI9），但连线和网络标号还没改。按交接给的理由（C3 只有 GPIO0-GPIO5 能深睡唤醒，SQW 必须在 0-5），这两条是后续必须做的。

### 4.5 顺带发现：BS1 与 `eink-arch.md` 说反了

`eink-arch.md` 第 65、100 行说"BS1 = 高电平 -> 4 线 SPI（直连 VDDIO）"。手册第 9 页 Note 5-5 的表是相反的：

```
BS1 = L -> 4-lines serial peripheral interface(SPI) - 8 bits SPI
BS1 = H -> 3- lines serial peripheral interface(SPI) - 9 bits SPI
```

板上 `FPC1-8(BS1) ∈ 3V3`，即 H，按手册选中的是 **3 线 9bit SPI**。但板子另外引出了 `D/C#`（第 11 脚）且 D/C# 语义（Note 5-2）就是 4 线 SPI 用的命令/数据区分脚，固件 `eink-arch.md` 的驱动逻辑也是按 D/C# 分开的 4 线方式写的。若确实要走 4 线 SPI，**BS1 应接低（GND）而不是 3V3**。这条与 `eink-arch.md` 的记载相反，和 4.2 一起构成"文档可能是错的"的又一处，需要人工拍板。

## 五、新引入的问题

按"基线没有、当前才有"的口径：

1. **没有发现新的硬短接或新的电源域错误。** 这轮改动是收敛性的，没有把原来的错扩大到别处。
2. **GPIO9、GPIO10 现在完全悬空。** 删掉 R13/R14 后，这两根线既没接上拉也没接负载。作为"已释放"是正常的；但如果按 4.4 的计划要把 CS# 挪到 GPIO9，届时 CS# 通常希望有个上拉（默认不选中），现在没有。不算当前 bug，先记着。
3. **`C1` 的归属变了。** 原来 `C1` 在 `FPC1-18` 单独那条网上，现在跟着并到 3V3。若最终裁定第 18 脚不该接 3.3V（4.2.1），那 C1 要跟着从 3V3 挪走，`3V3` 上的去耦会再少一颗（第 12 条更薄）。

没有发现"改出错"的典型形态（没有新增单节点电源脚、没有把某脚改到错误电源、没有引入新的双驱动）。唯一"改错方向"的是第 18 脚（见 2.5），但那是照着一份可能有错的文档改的。

## 六、没能确认的项，以及缺什么

以下几条我拿不准，明确标出来，不做定论：

1. **第 18 脚 VDD 到底能不能接 3.3V。** 手册文字和典型电路都说只挂电容、VDD 由 VCI 内部稳压，按此当前接法是错的。但"内部稳压输出与外部 3.3V 并接会怎样"需要面板电气特性页（我没有逐页 OCR 全手册）。缺：该面板的 DC Characteristics / 内部电源结构说明，或厂商 FAE 确认。
2. **第 9 脚 BUSY 是否必须外部上拉。** 手册典型电路没画上拉，但它接的是 strapping 的 IO8。缺：ESP32-C3 数据手册里 IO8 复位期间内部上拉的有无与强度，以及面板 VCI 上电到 BUSY 有效的时序。有了这两样才能判断要不要补 100K 上拉。
3. **升压电路是否真的必须外置。** 第 24 页流程图写 "DC/DC regulator to generate the drive voltage"，读起来像面板内部有 DC/DC；但第 23 页又把功率级画在外面、第 8 页 GDR/RESE 也定义成对外脚。缺：该面板的推荐应用 / 电气规格页，确认"内部 DC/DC + 外部功率级"还是"整块外置"。这直接决定 4.3 的"板子缺升压"是致命还是无关。
4. **FPC 符号 25/26 脚对应封装哪两个焊盘。** `lib_Footprint.get` 在本环境报错，拿不到焊盘清单（README 已记这个坑）。缺：`FPC-05F-24PH20` 的封装焊盘定义（是否 24 焊盘 + 2 固定/接地脚）。
5. **五向开关阻值↔方向（第 14 条）。** 需要实物通断档核对，网表看不出方向。
6. **本次快照是否为用户最终保存态。** 导出时工程正被编辑（备份时间 19:18 晚于页面 19:08）。如果用户在本次导出之后又改了，需重新导一次再对账。

## 七、给用户的一句话结论

**两条灾难级里，C6 那条真修好了，I2C/SPI 短接那条只修了 SCL、SDA 还短着，板子照现在就打样还是会把 I2C 和刷屏数据搅在一起。** 参数类的 R3/R6/R7 值改对了，但 R3 的 LED 回路、27K USB 串阻、EN1/ILIM/分压源、PGOOD、FPC 脚数这些都没动。两条待定的搬家（CS#->GPIO9、SQW->GPIO4）都还没落地。另外，第 18 脚 VDD 的改法、BS1 的选择、以及整块升压功率级的缺失，都要以厂商手册为准重新拍板，因为现行的 `eink-arch.md` 在这三处和手册对不上。

## 三、小窗内容池

### 数据结构（`ui.h`）

```c
#define UI_POOL_MAX 8

typedef enum {
    UI_ITEM_TEXT,     /* 文本：新闻 / 一言 */
    UI_ITEM_IMAGE,    /* 位图：插画 */
} ui_item_kind_t;

typedef struct {
    ui_item_kind_t  kind;
    ui_panel_kind_t text_kind;    /* 文本项有效 */
    char            title[24];
    char            body[256];
    int             image_id;     /* 位图项有效 */
} ui_item_t;
```

### API（替换 `ui_set_panel`）

```c
void ui_pool_clear(void);
void ui_pool_set_text(ui_panel_kind_t kind, const char *title, const char *body);
void ui_pool_set_images(const int *ids, int count);   /* 启动时扫盘后灌进来 */
int  ui_pool_count(void);
int  ui_pool_current(void);
void ui_pool_move(int delta);                          /* ±1，环形 */
```

### 池的构成（顺序固定，便于预期）

```
[0] 新闻（有则入池）
[1] 一言（有则入池）
[2..] 插画，按 id 升序
```

### 持久化

| 内容 | 存哪 |
|---|---|
| 新闻标题/正文 | NVS，`pool_news_title` / `pool_news_body` |
| 一言标题/正文 | NVS，`pool_quote_title` / `pool_quote_body` |
| 插画 id 列表 | **不存**，启动时扫 LittleFS 的 `img_*.bin` 得到 |
| 当前游标 | NVS，`pool_cur` |

### 轮换

| 触发 | 行为 |
|---|---|
| IDLE 下 上/下 | `ui_pool_move(±1)` + **整屏重绘** |
| RTC 唤醒 | `cfg_rotate` 为开时 `ui_pool_move(+1)` |
| 池为空 | 显示占位提示（如「暂无内容」） |

> **`cfg_rotate` 只控制自动轮换；手动上下永远能切。**（这是我定的，觉得反了就改）

## 四、插画显示

### 文件格式

`img_<id>.bin`，**裸位图**，无文件头：

| 项 | 约定 |
|---|---|
| 排列 | 行优先，MSB 在左 |
| 取值 | **1 = 黑**（与 PC 端上传的约定一致） |
| 尺寸判定 | **按文件长度反推** |

| 长度 | 尺寸 | 用途 |
|---|---|---|
| 15000 | 400×300 | 全屏 |
| 3400 | 134×200 | 小窗 |

长度对不上就跳过该项（并在日志里说一声），不要瞎画。

### 绘制

```c
void ui_draw_image_full(int image_id);   /* 铺 (0,0) */
void ui_draw_image_panel(int image_id);  /* 铺小窗内容区 (266,100,134,200) */
```

按 `cfg_art_mode` 选：

| `cfg_art_mode` | 轮到图片项时 |
|---|---|
| 0（全屏） | `ui_draw_image_full` → 再叠信息条（第五节） |
| 1（小窗） | 走普通布局（课表条 + 待办 + 小窗），图片只铺小窗 |

> 文本项（新闻/一言）**不受 `cfg_art_mode` 影响**，永远走普通布局。

## 五、信息条（只在「全屏 + 当前项是图片」时出现）

### 布局

条高定义为常量 `UI_BAR_H = 32`（**已定**）：

- 一行：左 `时间`，右 `第N节 科目`

> 全屏插画是拿来看的，不塞满。两行（64px）方案**已否决**。

数据来源：时间取 RTC；节次与科目取课表快照。**取不到就留空，不要写占位符。**

### 三种模式

```c
typedef enum {
    UI_BAR_SOLID = 0,       /* 实心黑条 */
    UI_BAR_INVERT = 1,      /* 反色整条 */
    UI_BAR_INVERT_AUTO = 2, /* 反色文字块 + 自适应字色 */
} ui_bar_mode_t;
```

| 模式 | 做法 |
|---|---|
| 实心 | 条内**填黑** → 画**白字** |
| 反色整条 | 条内**逐字节取反** → 画**白字** |
| 反色自适应 | 逐文字段处理，见下 |

### 自适应算法（这是本次唯一需要动脑的地方）

对**每一段文字**（左段、右段各算一段）单独处理：

```
1. r = 该段文字的包围盒（16px 高那几行，左右各留 2px 边距）
2. d0 = 统计 r 内当前的「黑像素」个数
3. invert_rect(r)                       // 取反
4. dark_after = r.w * r.h - d0          // 取反后黑像素数
5. 若 dark_after * 2 > r.w * r.h  → 画白字
   否则                            → 画黑字
6. 按选定的颜色把这段字画上去
```

顺序不能颠倒：**先取反，再统计（其实统计等价于反着算），最后画字**。

代价：一段字大概 16×80 像素 ≈ 160 字节要过一遍，两段加起来不到 0.5 KB，微秒级。

> 说明：整段共用一个字色（不是逐字），避免一个字黑一个字白。段内明暗混杂时仍可能有个别字看不清，这个先接受。

## 八、跨文件注意事项

1. **面板 RAM 极性与我们的 framebuffer 相反**（面板 1 = 白，我们 1 = 黑），刷屏那一层要取反。详见 `software-notes.md` 墨水屏一节。
2. **`img_<id>.bin` 的 id 由 PC 分配**，设备不回报，两端可能失步——已知限制，先接受。
3. **删除插画**本次不做（协议未定义删除消息）。
4. 池上限 8：先放文本项，再按 id 升序放图片，放满为止。**PC 端建议最多传 6 张**。

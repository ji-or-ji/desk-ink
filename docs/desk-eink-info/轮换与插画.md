# 小窗内容池与插画链路

> 更新：2026-09-17
> 状态：**设计草案**，待确认后交编码
> 上游：`ui-spec.md`（小窗轮换）、`protocol.md`（消息）、`architecture.md`（存储）

---

## 一、为什么写这份

排查发现两个缺口：

| 缺口 | 现状 |
|---|---|
| 小窗轮换没实现 | `ui.c` 只有单个 `s_panel`，`app.c` 里 IDLE 的上下键只调 `ui_redraw_panel()`，内容不变 |
| 插画只能收不能显示 | 固件端 `link.c` 分片接收完整（含 CRC），但 `ui_panel_t` 没有位图字段，`UI_PANEL_IMAGE` 只用于显示标题 |
| PC 端没有发送端 | `pc-tool/Services` 十个服务里没有插画相关 |

另外 `protocol.md` 只定义了「推送即覆盖当前内容」，**缺少"下一个 / 上一个"的语义**。

---

## 二、已定的方向

- **轮换由设备本地完成**（不依赖 PC），符合「平时不依赖电脑」的设计哲学
- 插画来源：**本地图片文件** 或 **图床 URL**，由 PC 端拉取
- **图像预处理放在 PC 端**（缩放、二值化、抖动），设备只收 1-bit 成品
- **插画的尺寸与摆放由配置项决定**（见第五节）

## 三、小窗内容池

### 数据结构（固件端）

把单个 `ui_panel_t` 换成「内容池」：

```c
typedef enum {
    UI_ITEM_TEXT,     /* 文本：新闻 / 一言 */
    UI_ITEM_IMAGE,    /* 位图：插画 */
} ui_item_kind_t;

typedef struct {
    ui_item_kind_t  kind;
    ui_panel_kind_t text_kind;    /* 文本项有效：NEWS / QUOTE */
    char            title[24];
    char            body[256];
    int             image_id;     /* 位图项有效：对应 LittleFS 的 img_N.bin */
} ui_item_t;

typedef struct {
    int        count;
    int        current;           /* 当前显示第几项 */
    ui_item_t  items[UI_POOL_MAX];/* 建议 UI_POOL_MAX = 8 */
} ui_pool_t;
```

### 轮换规则

| 触发 | 行为 |
|---|---|
| IDLE 下 上/下 | `current = (current ± 1 + count) % count` |
| RTC 唤醒（自动轮换） | `current++`，受 `cfg_rotate` 控制 |
| 收到 `news` / `quote` | 更新对应文本项；池中没有则追加 |
| 收到插画（`img_end` 完成） | 追加一个位图项，指向刚存的 `img_N.bin` |
| 池为空 | 显示占位提示（如「暂无内容」） |

> 「只存一份、覆盖」的旧行为要改成「入池」。池满时按最旧淘汰。

## 四、插画链路

### 4.1 PC 端（待实现）

```
本地图片文件 ─┐
              ├─→ 预处理（缩放→裁剪→二值化/抖动）─→ 1-bit ─→ 分片发送
图床 URL ────┘
```

**预处理参数**（PC 端可编辑）：

| 项 | 说明 |
|---|---|
| 目标尺寸 | 由 `cfg_art_mode` 决定：全屏 400×300 / 小窗 134×200 |
| 缩放方式 | 等比缩放 / 拉伸 / 裁剪填充 |
| 二值化 | 固定阈值（可调）/ 自适应 |
| 抖动 | 关 / 有序抖动 / 误差扩散（Floyd–Steinberg） |
| 反色 | 是 / 否 |

**传输**：沿用协议三段式（`img_begin` / `img_chunk` / `img_end`），固件端已就绪。

**管理界面**：图片列表、预览（按目标尺寸等比）、上传、抹除。

> 图床拉取要设超时（参考 `QuoteService` 的 10s），失败时保留上一次内容，不阻塞。

### 4.2 固件端

| 环节 | 状态 |
|---|---|
| 分片接收 + CRC 校验 | ✅ 已有 |
| 落 LittleFS | ✅ 已有 |
| **绘制到屏幕** | ❌ **缺** |

需要补：从 `img_N.bin` 读 1-bit 数据 → `fb_blit_1bit` 画到对应区域。

## 五、插画显示模式（配置项）

配置项：`cfg_art_mode`（NVS，默认 0）

| 值 | 模式 | 尺寸 | 行为 |
|---|---|---|---|
| `0` | **全屏叠加** | 400×300 | 插画铺满整屏；信息条叠在**上方**，遮挡处**反色** |
| `1` | **小窗** | 134×200 | 插画放进右列小窗，PC 端裁剪/缩放保证尺寸正常 |

### 模式 0：全屏叠加

```
┌──────────────────────────────┐
│ ▓ 09:40 · 第3节 数学 ▓       │ ← 信息条，局部反色
│                              │
│                              │
│        插画（400×300）        │
│                              │
│                              │
└──────────────────────────────┘
```

- 反色在**设备端**做（见第六节）
- 时间、节次是动态的，每次刷新都要重叠

### 模式 1：小窗

沿用现有「一屏多区」布局，插画占右列小窗内容区（134×200），课表条与待办照常显示。

- 缩放/裁剪由 **PC 端**完成
- 设备端无叠加逻辑，渲染分支最简单

### 模式切换的坑

两种模式产出的图**比例不同**（4:3 vs 约 2:3），已存的图切过去会变形。处理方式二选一：

- **简单**：切模式时清空 `img_*.bin`，让 PC 重推
- **精细**：每张图记录自己的宽高，显示时不匹配就跳过

> 先按「简单」来，插画本来就可以重传。

## 六、反色的实现（设备端）

只对**文字笔画所在矩形**取反，不是整区翻转（整区翻会让黑底配黑字看不见）：

```c
/* 位图是 1-bit packed，每字节 8 像素 */
for (int i = start; i < end; i++) {
    fb[i] ^= 0xFF;
}
```

- 成本：15KB 全图反色约几十微秒，局部反色更不值一提
- 边距：反色区比文字外扩约 2px，否则边界会显脏

## 七、已定 / 待定

**已定**（落地版见 `变更-显示侧.md`）：

| 项 | 结论 |
|---|---|
| 插画显示模式 | `cfg_art_mode`：0 全屏 / 1 小窗，默认 **0** |
| 信息条模式 | `cfg_bar_mode`：0 实心 / 1 反色整条 / 2 反色自适应，默认 **0** |
| 内容池上限 | 8 |
| `cfg_rotate` 与手动 | 关掉只影响**自动**轮换，手动上下永远能切 |
| 信息条高度 | **32px（已定）**，常量 `UI_BAR_H` |

1. PC 端预处理要不要「实时预览」（改参数立刻看到 1-bit 效果）
2. 插画淘汰策略（当前：池满 8 项，图片按 id 升序取）

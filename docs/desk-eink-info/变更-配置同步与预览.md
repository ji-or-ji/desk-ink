# 设计变更请求 — 设备配置只读同步 + 预览合成模式

> 日期：2026-09-18
> 面向：编码工具（opencode）
> 前提：**设备是配置的主角，PC 是辅助**。设备大部分时间脱离电脑运行，本地配置页随时可用。
> 因此 PC **只镜像、不覆盖**。

---

## 一、本次做两件事

| # | 内容 | 端 |
|---|---|---|
| A | 设备上报当前配置，PC 只读展示 | 设备 + PC |
| B | PC 预览区加「合成模式」下拉，**默认跟随 A 上报的值** | PC |

B 依赖 A：有了 A，预览才不会和设备实际设置打架。

---

## 二、A. 只读配置同步

### 2.1 新消息 `cfg`（设备 → PC）

全量，每次发完整的六项：

```json
{"t":"cfg","refresh":1,"pomo_focus":25,"pomo_break":5,
 "rotate":1,"art_mode":0,"bar_mode":0}
```

约 88 字节，一帧装得下（上限 255）。

| 字段 | 取值 | 默认 |
|---|---|---|
| `refresh` | 0 自动 / 1 常规 / 2 静默 | 1 |
| `pomo_focus` | 15 / 25 / 45 | 25 |
| `pomo_break` | 5 / 10 | 5 |
| `rotate` | 0 关 / 1 开 | 1 |
| `art_mode` | 0 全屏 / 1 小窗 | 0 |
| `bar_mode` | 0 实心 / 1 反色 / 2 反色自适应 | 0 |

字段名与 NVS key 一一对应（去掉 `cfg_` 前缀），**以后加配置项就往后加字段，不改已有字段名**。

### 2.2 设备端改动

| 文件 | 改什么 |
|---|---|
| `components/link/include/link.h` | 定义 `link_cfg_t`（六个 int）；声明 `esp_err_t link_send_cfg(const link_cfg_t *)` |
| `components/link/link.c` | 实现 `link_send_cfg()`，照 `link_send_schedule()` 的写法 |
| `components/app/app.c` | 加 `push_cfg()`；**在两个时机调用**（见下） |

**发送时机（就这两个）**

1. `hello` 发出之后紧跟着发一次 —— 这样 PC 一连上就知道设备现状
2. 设备本地配置页**保存**之后发一次 —— 这样 PC 的显示能跟着变

> PC 收到 `hello` 后本来就会全量推 `schedule`；设备这边同理，`hello` 后补一条 `cfg`。

### 2.3 PC 端改动

| 文件 | 改什么 |
|---|---|
| `Models/Protocol.cs` | 加 `ConfigMessage`（六个 `int`，`[JsonPropertyName]` 对齐上表） |
| 收行分发处 | 加一个 `t == "cfg"` 分支，更新内存里的设备配置快照 |
| `Pages/SettingsPage.xaml` | 加「**设备配置**」区：六行只读展示 + 一个「最近同步」时间戳 |

**展示要求**

- 每行：名称 + 当前值文案
- **未连接 / 尚未收到 `cfg` 时显示「—」，不要显示默认值**（显示默认值就等于撒谎）
- 值 → 文案的映射**必须与设备端 `config_value_label()` 一字不差**：

| 项 | 文案 |
|---|---|
| 刷新档位 | 自动 / 常规 / 静默 |
| 番茄钟专注 | `25 分`（数值 + 空格 + 分） |
| 番茄钟休息 | `5 分` |
| 小窗轮换 | 开 / 关 |
| 插画显示 | 全屏 / 小窗 |
| 信息条 | 实心 / 反色 / 反色自适应 |

## 三、B. 预览加「合成模式」下拉

现在预览只是一张 1-bit 位图。加一个下拉，切换**合成后的样子**：

| 选项 | 画什么 |
|---|---|
| 仅插画 | 现在的行为 |
| 全屏 + 实心条 | 400×300 铺满 + 顶部 32px 黑条白字 |
| 全屏 + 反色条 | 同上，条内取反 |
| 全屏 + 反色自适应 | 同上，逐段自适应字色 |
| 小窗模式 | 插画缩到 134×200，画在右列小窗位置 |

**硬要求：必须用设备真字库。** 把 `software/font/font16_simsun.bin`（131 KB）与 `ascii8x16.bin`（1.5 KB）随工具打包，按 `font16_simsun.bin` 的 `F16B` 格式取字模。

> 用系统字体渲染的预览是**假的**：字宽不同，信息条长度就不同。

**下拉默认值**：跟随 A 上报的 `art_mode` / `bar_mode`；未收到上报时才回落到「仅插画」。

**信息条内容**用占位值即可（如 `09:40` / `第3节 数学`），不必接真实课表——预览的目的是看**版面和可读性**，不是看数据对不对。

**不要做的**：别预览 POMO / TODO_NAV / TODO_EDIT / MENU / CONFIG。那些没有插画介入，PC 上复刻它们等于把 `ui.c` 抄第三遍。

---

## 四、⚠️ 硬规则：连接时 PC 不得推送配置

这是本次最重要的一条，**写死**：

```
PC 连上 → 设备 hello → 设备 cfg 全量上报 → PC 更新界面
                                               ↑
                                          到此为止，PC 不改设备
```

理由很实际：用户在设备上刚调好的东西，如果 PC 一连上就用自己的存档推下去，**当场被覆盖**——「设备可脱离 PC 单独配置」这条就废了。

本次是**只读**，所以 PC 端**根本不该有写入口**。等第二步再谈写回。

---

## 五、第二步（本次只留接口，不实现）

将来若要 PC 也能改：

```json
{"t":"cfg_set","key":"bar_mode","value":2}
```

- **单项**下发，不是全量
- 冲突策略：**后写覆盖**（每次改动都双向广播，实际会自己收敛）
- 仍然遵守第四节那条：连接时不得自动推送

> `cfg_set` 本次**不实现**。设备端收到未知类型按现有规则丢弃即可。

## 七、验收

1. 设备上电 → 串口能看到一条 `cfg`，字段与设备实际设置一致
2. 在设备配置页把「信息条」改成「反色自适应」→ 串口又出一条 `cfg`，值变了
3. PC 端「设备配置」区六行与设备一致；断开连接后显示「—」
4. 预览下拉切五种模式，出图与 `tools/render-preview.ps1` 同参数结果一致
5. 预览里的汉字清晰（字库生效）

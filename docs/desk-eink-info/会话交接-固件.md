## 三、最近的关键结论（别忘）

| 结论 | 说明 |
|---|---|
| 屏幕是**黑白双色** | 规格书 V2.0 第 5 页；没有红色可用 |
| 驱动 IC 是 **SSD1619AZ** | 不是 SSD1680（已改 8 处文档） |
| 面板 RAM **1 = 白** | 我们的 framebuffer **1 = 黑**，刷屏前**每个字节要取反** |
| 字库补了**第 3 区** | 以前漏掉全角字母数字，字形 3943 → ~4037 |
| QEMU **已跑通** | 卡死根因是 `adc_oneshot_new_unit()` 自校准 + `eink_init()` SPI，QEMU 都不模拟 → `APP_SKIP_INPUT` / `APP_SKIP_EINK`；配方与坑见 `qemu-验证.md` |
| QEMU 缺 `libiconv-2.dll` | `qemu-system-riscv32.exe` 导入它但 `bin\` 没有；把含该 DLL 的目录加进 PATH 即可 |

## 四、已知的隐患与未决

1. **五向开关分压网络与唤醒阈值冲突**（**硬件隐患，板子还没改**）
   数字输入要判 LOW 得低于 0.825 V，但现在是：上 0.30 / 下 0.59 / 左 0.92 / 右 1.33 / **中央 1.98 V**。
   也就是说**拨左/右/中央很可能唤不醒**（中央几乎肯定不行）。
   建议改法（PCB 未布线，改了免费）：上拉 10k → **100k**，方向电阻改 **1k / 2.7k / 5.6k / 12k / 22k**。
   详见 `encoder-arch.md`，**最终阈值以实测为准**。

2. **`eink_flush_partial()` 有意留白** —— 需要独立 LUT，等整屏跑通再做。

3. **QEMU 已跑通验证** —— 带 `APP_SKIP_INPUT/APP_SKIP_EINK` 重建后能走到 `app_main`，
   `dump_fb_ascii` 出图，`hello`/`cfg`/`todo` 都能在串口看到。配方见 `qemu-验证.md` 第四节。

### 待办的实际情况（重要）

**已经做了：** `ST_TODO_NAV` 的中央短按接线了 —— 翻转 `done` → `todos_save()` → `send_todos_to_pc()`，
顺带还修了光标越界（`if (s_todo_cursor < s_todos.count)`）。

**还没做：分片。** `link_send_todo()` 仍是**旧单帧版**：

```c
char buf[LINK_LINE_MAX];
snprintf(buf, sizeof(buf), "{\"t\":\"todo\",\"items\":[");
...
if (... n + il + 4 > (int)sizeof(buf)) {
    ESP_LOGW(TAG, "todo frame full, truncated at item %d", i);
    break;
}
```

**后果**：8 条中文待办约 590 字节，被截到 3 条左右；而 `todo` 是全量覆盖语义，
对面收到残缺列表会把缺的**当成删除**。所以现在设备回传的待办**会丢条目**。

接收端（`parse_todo`）同样还是单帧，没有 `seq`/`total` 累加。

## 三、最近的关键结论（别忘）

| 屏幕是**黑白双色** | 规格书 V2.0 第 5 页；没有红色可用 |

## 四、已知的隐患与未决

1. **五向开关分压网络与唤醒阈值冲突**（**硬件隐患，板子还没改**）
   数字输入要判 LOW 得低于 0.825 V，但现在是：上 0.30 / 下 0.59 / 左 0.92 / 右 1.33 / **中央 1.98 V**。
   也就是说**拨左/右/中央很可能唤不醒**（中央几乎肯定不行）。
   建议改法（PCB 未布线，改了免费）：上拉 10k → **100k**，方向电阻改 **1k / 2.7k / 5.6k / 12k / 22k**。
   详见 `encoder-arch.md`，**最终阈值以实测为准**。

2. **`eink_flush_partial()` 有意留白** —— 需要独立 LUT，等整屏跑通再做。

3. **QEMU 还没实际跑通验证** —— 开关就位了，但需要带 `APP_SKIP_INPUT/APP_SKIP_EINK` 重建一次。
   跑通后 `app.c` 的 `dump_fb_ascii(100, 30)` 会打出 framebuffer，就是**真代码渲染的结果**。

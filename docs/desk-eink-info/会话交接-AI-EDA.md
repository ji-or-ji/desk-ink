> **面向：新的 opencode 会话**
> 你跟前几个会话（硬件/固件、PC 工具、Bad Apple demo）**不互通**，上下文全在这份文档里。

## 一、这不是开发任务，是一次测边界的实验

用户想验证一件事：**AI 到底能多深地参与电路设计**。

前面已经做了一轮桌面调研，结论是：**"AI 能做什么"基本清楚了，但"AI 改完设计能不能安全落盘"没有任何先例。** 这一轮就是去撞这面墙。

所以你**不要追求"跑通"**。你要的是：

1. **断在哪一步**（越具体越好）
2. **断在哪一类**：权限 / API 缺口 / 环境 / 模型能力 / 必须人工
3. **原始证据**：报错原文、日志、截图

**跑通了是结果，跑不通也是结果，但"大概不行"不是结果。**

## 二、环境已经探明，别重复摸索

### 官方立场

- **编辑器本体没有内置 AI。** 官方把 AI 放在外面，通过扩展体系接入。
- 官方文档有专门一页《For AI：扩展工程初始化指南》，面向 Claude Code / OpenCode / QwenCode / Copilot：
  https://prodocs.lceda.cn/cn/api/guide/how-to-start-for-ai.html
  官方规定初始化扩展工程时"默认应当安装 `easyeda-api` Skill"。
- 官方桥接扩展 **Run API Gateway**（发布者 EasyEDA）："为 AI 编程工具提供 WebSocket 网关桥接服务"，**端口 49620-49629**。
  https://jlc-ext.com/item/oshwhub/run-api-gateway

### 链路形态

```
AI 工具（opencode）
   ↓  easyeda-api Skill
Bridge Server（本地进程）
   ↓  WebSocket
Run API Gateway 扩展
   ↓
立创EDA 专业版（打开着的工程）
```

### 几条会拦住你的硬限制

| 限制 | 原文/说明 |
|---|---|
| **导入扩展是 GUI 步骤** | 官方明说 **AI 无法代办**，必须用户手动装 |
| **外部交互权限** | 不勾选，`SYS_ClientUrl.request` 会**永远 throw Error**。扩展管理器里那个叫"外部交互"的开关 |
| **CORS** | 官方原文："需要在被请求的站点上允许跨源资源共享（CORS），否则接口将始终返回错误结果。"→ **在扩展里直连 OpenAI/DeepSeek 会被拦**，必须走本地 Bridge 中转 |
| **BETA** | 核心链路（建工程/建板/自动布局/自动布线/设计规则/DRC/导出 Gerber）**全挂 BETA**。BETA 的官方定义原文："**请不要将它用于任何正式环境**" |
| **没有事务/撤销/回滚** | 全量 API 类清单里找不到任何 `Undo` / `Transaction` / `History` |
| **没有工程级 save** | `SCH_Document.save()` / `PCB_Document.save()` 存的是**文档**，不是工程文件 |
| **同一文档无锁** | 官方协作只对"不同文档"并发安全。同文档靠"别同时编辑"的纪律，否则**保存互相覆盖** |

### 少数非 BETA 的可靠接口

- `PCB_Document.importChanges(uuid)`：转 PCB / 导入变更 ✅

### 工程文件是什么（已自验）

- `.eprj2` = **SQLite 数据库**（文件头 `SQLite format 3`，我已经验过）。表里有 `components` / `devices` / `coppers` / `boards`，每行 `dataStr` 存 JSON。
  **官方从未公开这个结构。**
- `.epro` = 导出的工程包，内含 **V3 源码格式**：逐行 JSON，每行两个 JSON 用 `||` 拼，外层靠 `type/id/ticket/client` 定序（**CRDT 式最终一致性**）。
  → **外部想写回这个格式，必须先自己实现逻辑时钟与冲突裁决**，否则一写就覆盖或判废。
- 工程默认存在 `Documents\LCEDA-Pro\projects\`

### SDK 与文档

- SDK：`gitee.com/jlceda/pro-api-sdk`（**Gitee，国内可达**）；类型定义 npm `@jlceda/pro-api-types`
- API 参考：https://prodocs.lceda.cn/cn/api/reference/pro-api.html
- 文件格式：https://prodocs.lceda.cn/cn/format/index/

## 三、已经知道了什么（别再去撞已知的墙）

前面两轮调研的边界结论，你**不需要重新验证**：

| 卡在哪 | 类别 | 有没有人翻过去 |
|---|---|---|
| PCB **布线** | 模型能力（几何 + 多约束） | 没有。实测案例原话："原理图审核很强，pcb 布局也可以"，**布线翻车** |
| **语义/工艺/选型审查** | 必须人工 | 结构上查不出：引脚顺序颠倒、过孔载流不足、丝印盖焊盘、封装与引脚编号脱钩、器件选型 |
| **写回工程** | 别人的地盘 | **无任何先例** ← **这才是你要撞的** |
| CORS + 外部交互权限 | 环境 | 只能绕本地桥 |

完整清单见 `docs/desk-eink-info/ai-eda.md`。

## 四、实验设计：从最深往回退

**顺序很重要**：既然目标是找边界，就从最深的那档开始，撞不动再退一档。**退界的那个点就是答案。**

### 第 0 步：前置（需要用户手动做，你指挥）

- [ ] 装 Run API Gateway 扩展
- [ ] 在扩展管理器里**勾选"允许外部交互"**
- [ ] 确认 Node.js ≥ 20.17
- [ ] **把工程复制一份当靶子**（见下节安全规则）
- [ ] 在立创EDA 里打开那个副本工程

### 第 1 撞：AI 改一个器件

让 AI 通过 API 把一个电阻换个阻值（比如 R12）。**目标是看它能不能落盘。**
记录：调用了什么、返回什么、编辑器里有没有变、磁盘上有没有变。

### 第 2 撞：并发

编辑器同时开着，AI 改的同时用户手动改另一个地方。
记录：会不会冲突、会不会覆盖、有没有任何提示。

### 第 3 撞：DRC + 回读

跑一次 DRC（`PCB_Drc.check`），把结果读回来。**目标是看"改 → 检查 → 回读"这条闭环能不能自己闭上。**

### 第 4 撞：加一条网络 / 放一个器件

比改阻值更深。看 API 覆盖够不够。

### 每一撞都要记

```
做什么 → 调了什么 API → 结果 → 断在哪 → 归类（权限/API缺口/环境/模型能力/必须人工）
```

## 五、安全规则（**最重要的一节**）

**没有事务、没有锁、没有回滚 API。** 所以：

1. **先备份。** 动手前把 `bord/桌面小摆件.eprj2` 复制一份到别处。写坏了这就是唯一的退路。
2. **在副本工程上做实验，不在正式工程上。** 正式工程在 git 里跟着走，别拿它当靶子。
3. **别让 AI 和用户同时编辑同一个文档。** 官方无锁，会互相覆盖。
4. **每一步之前先存盘。** 社区扩展作者的原话就是"工具能改工程，操作前先存盘"。
5. 写坏了：编辑器 GUI 有"版本管理 / 缓存恢复 / 版本切换"，**但那没有 API**，只能人工点。

## 六、硬规则

1. **改动留在工作区，不要 `git commit`。** 由助理审阅后统一提交。
2. **每一步都报告**：做了什么、调了什么、结果是什么、断在哪。
3. **不要访问 GitHub**（用户学校网络会监控，会被抓）。Gitee、CSDN、知乎、B站可以。
4. **写作风格**：不用 `「」`（用 `""`）、不用破折号 `——`、中英之间不加刻意空格、段落不硬换行。
5. **拿不准就说拿不准**，不要用"理论上可以"填空。
6. 官方文档出现与本文档冲突的说法时，**以官方文档为准**，并把这个冲突报告出来。

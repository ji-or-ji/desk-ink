## 接线

| 开关引脚 | 名称 | 连接 |
|:--------:|:----:|------|
| COM | 公共端 | GPIO 0（分压中点） |
| 上 | 方向触点 | 1.0kΩ → GND |
| 下 | 方向触点 | 2.2kΩ → GND |
| 左 | 方向触点 | 3.9kΩ → GND |
| 右 | 方向触点 | 6.8kΩ → GND |
| 中央 | 中央触点 | 15kΩ → GND |
| — | 上拉 | 10kΩ → 3.3V（GPIO 0） |

**关键**：必须是「四个方向各自独立引出」的型号，避开矩阵式接法（矩阵式无法用单脚分压区分）。

## 电压判读表（R0 = 10kΩ）

| 动作 | 分压电阻 | GPIO0 电压（计算） |
|---|---|---|
| 上 | 1.0kΩ | ≈0.30 V |
| 下 | 2.2kΩ | ≈0.59 V |
| 左 | 3.9kΩ | ≈0.92 V |
| 右 | 6.8kΩ | ≈1.33 V |
| 中央 | 15kΩ | ≈1.98 V |
| 不拨 | ∞（仅上拉） | ≈3.3 V |

## ⚠️ 唤醒阈值的矛盾（2026-09-17 发现，待实测）

上面那张表是按「ADC 要拉开五档」算的，但它和「数字输入要够低才能唤醒」是**打架的**。

数字输入 V_IL(max) ≈ 0.25 × VDD = **0.825 V**。对照：

| 动作 | 电压 | 能否被当 LOW |
|---|---|---|
| 上 | 0.30 V | ✅ |
| 下 | 0.59 V | ✅ |
| 左 | 0.92 V | ❌ |
| 右 | 1.33 V | ❌ |
| 中央 | 1.98 V | ❌ **明显过高** |

**结论：按现值，拨「左 / 右 / 中央」很可能唤不醒设备**（而人最自然的动作恰好是按中央）。

### 改法已定（2026-09-18）—— ⚠️ **硬依赖，不是可选优化**

**为什么是硬依赖**：`input.c` 的判读阈值（`TH_UP_MAX` **74** / **166** / **324** / **582** / **2000**）
就是按下面这组值算的（理论计数 40 / 109 / 223 / 426 / 738，取相邻中点）。

用旧值的话 ADC 读数会整体**高一个量级**（上 372 / 下 732 / 左 1142 / 右 1650 / 中央 2458），
判读会**全错**——比如拨「上」会被认成「右」。

**PCB 尚未布线（最后动是 2026-05-30），现在改是零成本。**

### 建议值

| 项 | 现值 | 建议值 |
|---|---|---|
| 上拉 R0 | 10 kΩ | **100 kΩ** |
| 上/下/左/右/中央 | 1k / 2.2k / 3.9k / 6.8k / 15k | **1k / 2.7k / 5.6k / 12k / 22k** |

改后全档位都远低于 0.825 V，任意方向都能唤醒，且档位间距（ADC 计数）仍够：

| 动作 | 电压 | 计数 | 间距 |
|---|---|---|---|
| 上 | 0.033 V | ≈ 40 | — |
| 下 | 0.088 V | ≈ 109 | 69 |
| 左 | 0.180 V | ≈ 223 | 114 |
| 右 | 0.343 V | ≈ 426 | 203 |
| 中央 | 0.595 V | ≈ 738 | 312 |

按下时电流 ≈ 27 µA，可忽略。

> 详见 `变更-固件阶段二.md` 第二节。最终阈值以实测为准，代码里做成 `#define`。

## 双身份：EXT1 唤醒 + ADC 读方向

同一个 GPIO 0 在深睡前后的两种用法：

```
深睡前：
  配成数字输入（上拉），任意方向按下都会把 GPIO0 拉低
  esp_deep_sleep_enable_ext1_wakeup(1 << 0, ESP_EXT1_WAKEUP_ANY_LOW)
  → 拨动即唤醒，静态零功耗

唤醒后：
  切换成 ADC1_CH0，读分压值 → 查表判方向 → 分发事件
  处理完 → 重新配回数字输入 → 再次深睡
```

## 注意事项

- GPIO 0 **不是** strapping 脚（C3 的是 GPIO2 / GPIO8 / GPIO9），可安全用作唤醒源
- C3 的 ADC 有非线性，各档间隔要大过校准误差；实测后微调分压电阻或加软件标定
- 消抖在软件里做（同一方向连续采样一致才确认）
- 若最终只用五向开关，原编码器占用的 **GPIO9 / GPIO10 可释放**

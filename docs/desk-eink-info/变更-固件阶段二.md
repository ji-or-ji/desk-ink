## 二、`input` —— 五向导航开关

### 2.1 硬件（照 `gpio-map.md` / `encoder-arch.md`）

`GPIO0`（ADC1_CH0），上拉 10kΩ → 3.3V，各方向串不同阻值到 GND：

| 动作 | 分压电阻 | 电压（算） |
|---|---|---|
| 上 | 1.0kΩ | 0.30 V |
| 下 | 2.2kΩ | 0.59 V |
| 左 | 3.9kΩ | 0.92 V |
| 右 | 6.8kΩ | 1.33 V |
| 中央 | 15kΩ | 1.98 V |
| 不拨 | ∞ | 3.3 V |

### 2.2 ⚠️ 一个必须先解决的硬件问题：唤醒阈值

方案写的是「深睡前配**数字输入**，`EXT1_WAKEUP_ANY_LOW`，拨动即唤醒」。

但数字输入的 **V_IL(max) ≈ 0.25 × VDD = 0.825 V**。对照上表：

| 动作 | 电压 | 能否被判定为 LOW |
|---|---|---|
| 上 | 0.30 V | ✅ |
| 下 | 0.59 V | ✅ |
| 左 | 0.92 V | ❌ 偏高 |
| 右 | 1.33 V | ❌ 偏高 |
| 中央 | 1.98 V | ❌ **明显过高** |

**也就是说：当前分压网络下，拨「左 / 右 / 中央」很可能唤不醒设备**（中央尤其肯定）。而人最自然的唤醒动作恰恰是按中央。

> 这是「分压要拉开五档」和「数字输入要够低」之间的矛盾：要拉开档位就得有大电阻，大电阻又把电压顶高了。

**建议改法**（PCB 还没布线，现在改是免费的）：

| 项 | 现在 | 建议 |
|---|---|---|
| 上拉 R0 | 10 kΩ | **100 kΩ** |
| 上 / 下 / 左 / 右 / 中央 | 1k / 2.2k / 3.9k / 6.8k / 15k | **1k / 2.7k / 5.6k / 12k / 22k** |

改后电压与 ADC 计数（12-bit，11dB 衰减，约 1241 counts/V）：

| 动作 | 电压 | 计数 | 与下一档间距 |
|---|---|---|---|
| 上 | 0.033 V | ≈ 40 | — |
| 下 | 0.088 V | ≈ 109 | 69 |
| 左 | 0.180 V | ≈ 223 | 114 |
| 右 | 0.343 V | ≈ 426 | 203 |
| 中央 | 0.595 V | ≈ 738 | 312 |
| 不拨 | 3.3 V | ≈ 4095 | — |

全档位都远低于 0.825 V，**任意方向都能唤醒**；档位间距也够（最小 69 counts，高于 C3 的 ADC 噪声量级）。按下时电流 3.3V/(122kΩ) ≈ 27 µA，可忽略。

> 这条**需要实测复核**（C3 的 ADC 有非线性），但现值几乎肯定不行，先按建议值改。
> 代码里的判读表按最终实测值写，**阈值做成 `#define` 便于调**。

### 2.3 软件行为

```c
esp_err_t input_init(void);              /* 配 ADC1_CH0 + 采样任务 */
bool      input_poll(input_event_t *out);/* 非阻塞取事件 */
bool      input_woke_from_switch(void);  /* GPIO0 EXT1 唤醒 */
```

**采样与判读**

1. 周期采样（建议 20 ms 一次），用 `adc_oneshot`（ESP-IDF v6 的 API，**别用已 EOL 的 `driver/adc.h`**）
2. 多点平均（如 8 次）压噪声
3. 判读：落入哪一档的 ±窗口 内。不拨时 ≈4095
4. 去抖：同一档位连续 3 次采样一致才确认

**事件生成**

| 条件 | 事件 |
|---|---|
| 上 / 下 / 左 / 右 首次确认 | `INPUT_UP/DOWN/LEFT/RIGHT`（按下沿触发一次，不重复） |
| 中央按下后**松开**，按住时长 < 800 ms | `INPUT_CENTER_SHORT` |
| 中央按住 ≥ 800 ms（未松开） | `INPUT_CENTER_LONG`（立即触发，不等松开） |

> 长按阈值与采样周期都做成 `#define`，便于调手感。

**深睡双身份**

```
深睡前：
  gpio 配数字输入 + 内部上拉
  esp_deep_sleep_enable_ext1_wakeup(1ULL << 0, ESP_EXT1_WAKEUP_ANY_LOW)
唤醒后：
  切回 ADC 读方向 → 判读 → 分发
  处理完再切回数字输入，准备下次深睡
```

**唤醒来源**：`esp_sleep_get_wakeup_cause()` 为 `ESP_SLEEP_WAKEUP_EXT1` → `input_woke_from_switch()` 返回 true。

## 三、`eink` —— 整屏刷新

### 3.1 引脚（照 `gpio-map.md`）

| 信号 | GPIO |
|---|---|
| EINK RES# | 2 |
| EINK D/C# | 3 |
| EINK CS# | 4 |
| EINK BUSY | 8（输入，**高 = 忙**） |
| EINK SCL / SDA | 18 / 19（SPI，FSPI） |

### 3.2 ⚠️ 极性问题（最容易栽的地方）

面板 RAM 的约定是 **1 = 白，0 = 黑**（规格书 `0x24` 命令说明）；
而我们的 framebuffer 是 **1 = 黑**。

**所以 `0x24` 写图之前，每个字节要取反**（`~byte`）。不取反就是整屏反相。

### 3.3 初始化 + 刷新序列（照规格书 10.2，逐条来）

```
上电 → delay 10ms
RES# 低 → delay 200us → RES# 高 → delay 200us
等 BUSY 低
0x12                     软件复位
等 BUSY 低
0x74 ← 0x54              模拟块控制
0x7E ← 0x3B              数字块控制
0x2B ← 0x04 0x63         VCOM 控制
0x0C ← 0x8B 0x9C 0x96 0x0F   Booster 软启动
0x01 ← 0x2B 0x01 0x00    显示尺寸 / 驱动输出
0x11 ← 0x01              RAM 数据入口模式
0x44 ← 0x00 0x31         RAM X 地址
0x45 ← 0x2B 0x01 0x00 0x00   RAM Y 地址
0x3C ← 0x01              边框
0x18 ← 0x80              内置温度传感器
0x22 ← 0xB1              载入 LUT
0x20                     激活
等 BUSY 低
0x4E ← 0x00              RAM X 计数
0x4F ← 0x2B 0x01         RAM Y 计数
0x24 ← 15000 字节        写 BW 图（**取反后**）
0x22 ← 0xC7              图像更新
0x20                     激活
等 BUSY 低
```

**注意**

- `0x10 ← 0x01` 进深睡是**面板**深睡，与主控深睡是两件事；主控深睡前要调用它
- BUSY 轮询要**带超时**（建议 10 s），超时返回错误而不是死等
- SPI 用 `spi_master`（v6 仍可用），模式 0，建议 10 MHz 起步
- 复位后 `0x24` 写完要重新 `0x4E/0x4F` 设地址计数（本流程只刷一次，够用）

### 3.4 局部刷新

`eink_flush_partial` **本次先保持 `NOT_SUPPORTED`**（需要独立 LUT，风险高，留到整屏跑通之后）。

## 四、`rtc` —— DS3231

I2C 地址 **0x68**（与 MCP3021 共用 I2C 总线，GPIO5/6）。

```c
esp_err_t rtc_get_time(struct tm *out);
esp_err_t rtc_set_time(const struct tm *t);
esp_err_t rtc_set_alarm(const struct tm *t);
esp_err_t rtc_clear_alarm(void);
```

**要点**

- 时间寄存器 `0x00~0x06`：秒 / 分 / 时 / 日 / 月 / 年，**BCD 编码**，需转换
- 小时寄存器 bit6 是 12/24 小时制标志，**统按 24 小时制读**
- 星期寄存器同样 BCD（1~7），与 `ui_set_date` 的 0=周日 要换算
- 闹钟 1：`0x07~0x0A`；控制寄存器 `0x0E`（`INTCN`、`A1IE`），状态 `0x0F`（`A1F`）
- SQW 输出接 **GPIO7**，走 `EXT0` 唤醒
- I2C 总线**复用**：建议在 `main.c` 里建一次 `i2c_master_bus`，把 handle 传给 `rtc` 与 `power`，**不要各自建总线**

## 五、`power` —— MCP3021

I2C 地址 **0x4B**（A3T 后缀），**10-bit**。

**读法**：读 2 字节，10 位值在**高 10 位**：

```c
uint16_t code = ((uint16_t)hi << 2) | (lo >> 6);   /* 10 bit */
```

**换算**（VDD = 3.3 V 作参考，输入经 100k+100k 分压，故乘 2）：

```c
mv = code * 3300 / 1023 * 2;   /* 先乘后除，避免整除丢精度 */
```

`power_percent()` 已有（3.0V~4.2V 线性），**不用改**。

> 建议加一次上电自检：读不到 0x4B 就在日志里告警（硬件排查用）。

## 六、接线：把已有的东西接上

### 6.1 待办勾选回传（`app.c:352`）

现在中央短按只是重绘。补上：

1. 翻转 `s_todo.items[cursor].done`
2. 存 NVS（勾选状态要能过夜）
3. `link_send_todo(...)` 回传 PC（**函数已存在**，`link.c:412`，只是没调用）
4. 重绘

### 6.2 RTC / 电源接入 `app`

当前这两个模块在整个固件里**零调用**。补：

- `app_start()`：`rtc_init()` 后读一次时间 → `ui_set_date()` + `ui_set_clock()`
- 唤醒路径：判断是 RTC 闹钟还是按键，分别处理
- 定时（如每 30 分钟）读一次 `power_read_mv()`，低电时小窗角标提示（可选）

## 七、顺带：`ui.c` 的换行做禁则处理

现在 `draw_wrapped` 按像素宽度硬切，会把「半成品」拆成「半成 / 品」。

最小改法：**断行时做禁则检查** ——

- 行尾不能是开引号、开括号（`“ 《 （` 等）
- 行首不能是收尾标点（`，。、！？）》”` 等）

遇到违例就把该字符挤到上一行或推到下一行。规则表做成一维数组即可，别引库。

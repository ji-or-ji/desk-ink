## 二、要发什么（照一言的形式）

### 2.1 消息

```json
{"t":"news","title":"","body":"运动会彩排通知 下周三下午…"}
```

**`title` 留空，正文放 `body`。** 理由：

- 固件的面板渲染是「标题行一行 + 正文区自动换行」
- `title` 只占一行、最多 7 个汉字，**长标题会被切掉**
- `body` 自动换行，最多 49 个汉字
- 一言就是这么做的（`title` 空、文本进 `body`，面板头回落成「每日一言」）
- 新闻同理会回落成面板头「**新闻**」，正文区显示头条

> 协议字段不用改。将来若真要做「标题 + 摘要」两级，字段已备好。

### 2.2 长度硬约束（按设备几何反推）

| 项 | 上限 |
|---|---|
| `body` | **49 个汉字**（小窗正文区 7 字 × 7 行） |
| 帧长 | 49 汉字 = 147 字节 + JSON 外壳 ≈ 182 字节 < 255 ✅ |

**超出就截断并补「…」**，不要发过去让设备自己切。

## 三、来源（四种，照 `QuoteService` 的模子）

新建 `Services/NewsService.cs`，**结构直接对标 `QuoteService`**（同样的 `Start()` / `RefreshAsync(reason)` / `Changed` 事件 / `SourceText`）。

| 源 | 取什么 | 备注 |
|---|---|---|
| **RSS / Atom** | feed 最新一条的标题 | 用 `XDocument` 即可：RSS 取 `//item/title`，Atom 取 `//entry/title`。不用引第三方库 |
| **自定义网址（JSON）** | 从 JSON 里挑字符串字段 | 照 `QuoteService.FetchUrlAsync` 的"候选键名依次尝试"写法 |
| **本地文件** | 每行一条 | 取一行 |
| **手动填写** | 用户直接输入一段 | 最简单 |

**默认源**：RSS —— 新闻的天然形式。

**RSS 附带处理**：标题里常见的 ` - 来源名` 后缀可剥掉（可选，做了更好看）。

## 四、界面

`SettingsPage` 加「**新闻**」区：

- 源类型下拉（四项）
- 对应的输入框（feed 网址 / JSON 网址 / 文件路径 / 多行文本），随源类型切换显隐
- 「立即刷新」按钮
- 当前取到的文本预览 + 来源说明（照 `QuoteService.SourceText` 的做法）

## 五、推送时机

| 时机 | 说明 |
|---|---|
| 串口连接建立后 | 推一次 |
| 点「立即刷新」 | 推一次 |
| 可选：随课表推送一并带出 | 照待办那个 `PushTodoSwitch` 的做法，加一个开关 |

**设备是被动接收方**，不主动索取。PC 侧决定刷新节奏，**别设成定时高频**——设备大多时候不连电脑，推太勤只是费电。

## 八、验收

1. 设置页选 RSS，填一个 feed 网址，点刷新 → 拿到最新一条标题
2. 设备串口能看到一条 `t":"news"` 的消息，`body` 是那段文字、`title` 为空
3. 设备小窗轮换到「新闻」面板，**头条完整换行显示**，面板头是「新闻」
4. 超长标题被截断到 49 汉字并带「…」
5. 帧长 < 255 字节

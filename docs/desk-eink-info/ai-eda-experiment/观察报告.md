# 观察报告：让 AI 审一次真实的原理图

> 2026-09-24。实验对象：`bord/桌面小摆件.eprj2`（ESP32-C3 + 墨水屏信息站，**PCB 尚未布线**）。
> 执行：一个独立的 opencode 会话，走官方 `easyeda-api` Skill + Run API Gateway 扩展 + 本地 Bridge。
> 记录与原始证据：`docs/desk-eink-info/ai-eda-experiment/`

---

## 一、结论

**这一环能真用，但必须给它上下文。**

而且它在上板之前，抓出了**三条会让整轮打样作废的错误**。

---

## 二、实验怎么设计的

第一版设计有个洞，先说清，因为这决定了后来为什么要做两轮：

我最初只打算"闭卷"——不给 AI 任何项目文档。这个想法**混淆了两类完全不同的问题**：

| 类型 | 例子 | 需要上下文吗 |
|---|---|---|
| 客观硬伤 | 电容串在供电回路、LED 没有回路、引脚数不匹配 | **不需要** |
| 设计选择的对错 | 某个脚被什么功能占用、某组参数取值 | **需要**，否则会把"刻意的"报成"错的" |

它是**编码 agent**：不能读 PDF、不能联网、看不到数据手册。**闭卷一跑，第二类必然大量误报**，而误报会污染整个测量——我分不清是"它审得烂"还是"我没给料"。

**所以改成两轮：**

- **第一轮 · 闭卷**，且明确要求"**只报客观错误，不要评论设计选择**"
- **第二轮 · 开卷**，给 `docs/desk-eink-info/` 的文档和 `software/` 源码，且要求每条**标注类别**（客观错误 / 与约束冲突 / 需人工判断）并**引用具体条目**

---

## 三、两轮结果

### 第一轮（闭卷，只报客观错误）

报了 6 条 + 1 条低置信度。**没有一条误报**——它没去咬屏型号、strapping 占用、UART0 用途、分压取值这些"需要上下文才能判断"的东西，还专门写了一节「本轮没做的事（按约束）」。

最重的一条：**C6 串在 USB VBUS 与充电 IC 输入之间，充电输入没有直流回路。**

> **已由助理直接读网表核实** ✓：网络里只有 `U3-13 BQ24073-IN` 和 `C6-2` 两个节点，VBUS 到 IN 之间唯一的通路就是那颗电容。**插 USB 充不进电。**

净收获：这条**不在事先准备的答案清单里**。

### 第二轮（开卷，要求分类 + 引用）

**主动撤回了第一轮两条**：

- GDR / RESE / TSCL / TSDA 单节点网络 → 撤回。`eink-arch.md` 引脚表明写这四脚是"悬空（内部）"，**有意不接**
- U4 (DS3231) 的 VBAT 只挂电容 → 撤回。`software-notes.md` 明说"只挂了 10μF→GND，无纽扣电池"，**有意**

另有两条第 降级为"需人工判断"（文档里没给依据）。

**同时抓出第一轮完全漏掉的一类——网络级 / 约束级的错：**

| | 问题 | 性质 |
|---|---|---|
| **B1** | I2C 总线与墨水屏 SPI **短接** | 灾难级，**已由助理读网表核实** ✓ |
| B2 | 墨水屏 FPC 第 18 脚 VDD 没接 3.3V，只挂电容 | 屏没供电 |
| B3 | MCP3021 的 VDD 接 5V 而非 3.3V | 电池电压会读低约 34%，**直接毁掉省电主线** |
| B5 | GPIO18/19 经 27K 接 USB D+/D- | 27K 疑为 27Ω 之误，与"用 USB 下载"冲突 |
| B6 / B7 / B8 | EN1 接 3.3V、ILIM 直连 GND、分压取自 P+ | 均与文档冲突 |

**还额外列了三条固件侧疑点**（非原理图），其中一条是**只有同时看原理图和固件才能发现**的：

> `input.c` 里开了内部上拉，叠加原理图上的外部 100k，会改变分压网络的实际取值。

**这正是第二轮存在的意义**——第一轮它不可能碰到这种耦合项。

## 四、关键观察

1. **上下文的作用不只是"减少误报"，它解锁了一整类发现。**
   第一轮只能抓**元件级**（电容串了、LED 没回路）；第二轮能抓**网络级**（总线短接、供电接错）和**跨文件耦合**（分压值 ↔ 固件阈值）。

2. **它能正确区分"刻意的"和"写错的"。**
   两条撤回都有明确文档依据。这是"能不能当审查员"的真正判据——**只会挑错的工具没法用**。

3. **"闭卷"这一轮不能省。**
   只跑开卷，你永远分不清它漏掉的是"能力不够"还是"没给料"；只跑闭卷，你会被误报淹没。**两轮之差才是有效信息。**

4. **它抓到了人眼最容易漏的那类错。**
   B1 极可能是一个**网络标号放错位置**导致两个网络合并——在图上看两条线离得很远、毫无异常，**只有读网表才知道**。调研里点名的"网络标号命名冲突"就是这个。

5. **误报率低于预期。**
   调研阶段看到的说法是"高召回、低准确"。本轮没验证到"低准确"——**但很可能是"只报客观错误"这个约束反而帮它收敛了**。这个区别值得以后再测。

6. **它仍然只会"读"。**
   全程未修改工程，也**不应该**让它改：外部写回会被编辑器静默覆盖（见 `ai-eda.md` 附录 D 段）。**它的定位是审查员，不是绘图员。**

---

## 五、对项目本身的实际产出

**三条会让打样作废的错误在上板前被拦下**：C6 断路、B1 总线短接、B2/B3 供电接错。

一块板从画到焊到查错，代价是按周计的。**这一轮实验的经济价值已经超过了实验本身的成本。**

---

## 六、限制（别把结论外推）

- **它是编码 agent**：不能读 PDF 数据手册、不能联网核对参数。所以它对"选型对不对、参数合不合理"的判断能力**取决于项目文档里写没写**。文档没写的，它只能标"需人工判断"。
- **只做静态审查**：网表是静态的。时序、驱动能力、功耗、热、EMI——**网表里看不出来**。
- **依赖网表导出的正确性**。B1 这类结论有一层前提：导出的网表忠实反映原理图。本次已用两种导出方式（v1/v2）交叉，且助理独立复核过。
- **待核项**：B2 / B3 / B4 / B6 / B7 / B8 属会话报告，**助理只独立核实了 C6 与 B1**。其余需要看原理图确认。
- **只测了一个案子**。这是单案例观察，不是统计结论。

---

## 七、可复用的方法

1. **导出网表**（别让它只看截图）
2. **两轮**：闭卷（只报客观错误）→ 开卷（分类 + 强制引用）
3. **事先准备答案清单，且不要让被考者看到**（本次放在仓库外）
4. **评分看三个数**：召回、误报、**净收获（它提出了我们没想到的）**——第三个最重要
5. **要它标注"需人工判断"并说明缺什么信息**——这条让它的无知显式化，而不是拿废话填满

2. **第一轮第 4 条：U4(DS3231) 的 VBAT 只挂电容。撤回。**
   依据 `software-notes.md` 第 68 行："**VBAT 引脚：**只挂了 10μF→GND，无纽扣电池。掉电后时间只能保持几分钟到几十分钟。如需长时间断电保持，可加 CR2032 座。" 这是**有意为之**，不是漏接。

### 改判

3. **第一轮第 5 条：3V3 去耦只有 C12。改判为 C（需人工判断）。**

## 一、A 类：客观错误

### A1. C6 串在 USB VBUS 与充电 IC 输入之间，充电输入没有直流回路（同时属 B）

- **位置**：U3(BQ24073) 的 IN 脚（U3-13）；C6(1μF)。
- **网表**：`$1N171 = {U3-13, C6-2}`；`VBUS+ = {USB1-A4, USB1-A9, C6-1, C7-2, U2-1}`。两个网络之间**只有 C6 一条路径**。
- **为什么错**：电容隔直，VBUS 的 5V 到不了 IN，充电器没有输入。任何语境下都错。
- **B 引用**：`power-arch.md` 第 87 行"13 IN ... USB-C VBUS + 1μF+0.1μF → GND"、第 118-119 行"IN 输入电容 1μF + 0.1μF"。文档要求 VBUS 直连 IN、C6/C7 对地。
- **置信度**：高。v1 同样。

### A2. 充电指示 LED1 看不到导通回路（同时属 B）

- **位置**：LED1、R3(10K)、U3-9(CHG#)。
- **网表**：`$1N158 = {LED1-1(A), R3-2}`；`R3-1 ∈ GND`；`$1N157 = {U3-9, LED1-2(C)}`。即 LED 阳极经 R3 接 GND，阴极接 CHG#。
- **为什么错**：阳极在最低电位，任何 CHG# 电平下都不满足正向偏置，灯不会亮。
- **B 引用**：`power-arch.md` 第 83 行"/CHG ... LED + 1kΩ → GND"、第 129 行"/CHG LED 限流 1kΩ"。文档限流电阻是 **1kΩ**，原理图是 **10K**；且接法与"低有效状态脚点灯"的常规相反。
- **置信度**：中（"阳极在 GND"是事实；CHG# 开漏低有效属常见做法，但无数据手册逐字确认）。

## 二、B 类：与项目约束冲突

### B1（重要）I2C 总线与墨水屏 SPI 短接：GPIO5/6 ↔ GPIO18/19

- **网表**：
  ```
  GPIO18 = {FPC1-13, U1-13(IO18), U1-5(IO6), U2-5(MCP3021 SCL), U4-8(DS3231 SCL), R7-2, R16-2}
  GPIO19 = {FPC1-14, U1-14(IO19), U1-4(IO5), U2-4(MCP3021 SDA), U4-7(DS3231 SDA), R6-2, R15-2}
  ```
  即 IO5/IO6（I2C）和 IO18/IO19（SPI）以及两颗 I2C 器件、EINK 的 SCL/SDA 全在同一个网络上，IO5 与 IO19、IO6 与 IO18 被短接。
- **约束引用**：
  - `gpio-map.md` 第 37-38 行：I2C SDA=**5**、SCL=**6**；第 43-44 行：EINK SCL=**18**、SDA=**19**。
  - `software-notes.md` 第 172-176 行：I2C SDA=**GPIO 5**、SCL=**GPIO 6**；第 88-89 行：EINK SCL=**18**、SDA=**19**。
  - `main.c` 第 24-29 行：`I2C_SCL = GPIO_NUM_6`、`I2C_SDA = GPIO_NUM_5`。
  - `eink.c` 第 20-21 行：`PIN_SCK = GPIO_NUM_18`、`PIN_MOSI = GPIO_NUM_19`。
  - `变更-固件阶段二.md` 第 186 行："与 MCP3021 共用 I2C 总线，GPIO5/6"。
- **后果**：固件会同时把 5/6 配成 I2C、把 18/19 配成 SPI。因为两对脚被短接，SPI 刷屏的时钟/数据会直接灌到 I2C 总线上，I2C 器件被扰动；I2C 上拉也会加载 SPI 线。**这是一处硬冲突。**
- **置信度**：高（网表 + 固件双向确认）。

### B2（重要）墨水屏 FPC 第 18 脚（VDD）没有接 3.3V

- **网表**：`$1N23 = {FPC1-18, C1-1}`，`C1-2 ∈ GND`。第 18 脚只挂一颗 1μF 到地，**没有 3.3V**。
- **约束引用**：`eink-arch.md` 第 110 行"18 | VDD | C | 核心逻辑电源 | **3.3V + 1μF/25V → GND**"，第 79 行"VCC33 --> VDD"。
- **后果**：面板核心逻辑电源脚没有供电（若面板内部不自带该电源）。这既是客观电气问题（A），也明确冲突（B）。
- **备注**：`software-notes.md` 第 105 行的电容清单只写了"18 VDD 1μF→GND"，没写 3.3V，两份文档本身略有出入；但 `eink-arch.md` 明确要 3.3V。以 `eink-arch.md` 为准。
- **置信度**：中高（冲突明确；"面板是否内部自供"要面板规格书才能 100% 定）。

### B3. MCP3021 的 VDD 接在 USB VBUS(5V)，文档要求接 3.3V

- **网表**：`U2-1(MCP3021 VDD) ∈ VBUS+`。
- **约束引用**：
  - `power-arch.md` 第 161 行"MCP3021 接线 | VDD | **3.3V (LDO输出)**"。
  - `software-notes.md` 第 31 行"VREF | **VDD（3.3V）**"。
  - `变更-固件阶段二.md` 第 216 行"换算（**VDD = 3.3 V 作参考**）"。
  - `power.c` 第 44-46 行：`*mv_out = code * 6600 / 1023;`（6600 = 3.3×2×1000，**代码按 VREF=3.3V 算**）。
- **后果**：若 VDD 实际是 5V，ADC 满量程变成 5V，固件按 3.3V 换算会把电池电压读**偏低约 34%**（3.3/5）；且电池供电时该 ADC 无电。功能冲突。
- **置信度**：高。

### B4. I2C 上拉阻值 10K，文档要求 4.7kΩ

- **网表**：`R6(10K)`、`R7(10K)` 分别上拉到 3V3（在 GPIO19/GPIO18 网络上）。
- **约束引用**：`gpio-map.md` 第 37-38 行"4.7kΩ 上拉到 3.3V"；`software-notes.md` 第 174 行"4.7kΩ → 3.3V"。
- **置信度**：中（阻值是明确冲突；影响取决于总线速率）。

### B5. GPIO18/19 经 R15/R16(27K) 接 USB D+/D-

- **网表**：`$1N249 = {USB1-A7(DN1), R16-1}`、`R16-2 ∈ GPIO18`；`$1N248 = {USB1-A6(DP1), R15-1}`、`R15-2 ∈ GPIO19`。即 USB 数据线经 27K 串到 GPIO18/19。
- **约束引用**：`software-notes.md` 第 12 行"USB Serial/JTAG 下载口：GPIO18(USBD−)/GPIO19(USBD+) ... `idf.py flash` 自动进下载模式"；第 96-99 行"⚠️ GPIO18/19 复用 USB JTAG ... 烧录时由硬件接管下载"。
- **疑点**：USB 差分线上串 27K 会严重衰减信号，与"用 USB 下载"冲突（USB 串阻通常是 0~27Ω 量级）。原理图这两个值疑似应为 27Ω 或 0Ω。
- **置信度**：中（冲突存在；具体串阻要求要 ESP32-C3 USB 电气规格，本轮拿不到，故此条兼有 C 的性质）。

### B6. EN1 接在 3.3V(LDO 输出)，文档要求接 VOUT

- **网表**：`U3-6(EN1) ∈ 3V3`（3V3 是 U5 XC6206 的输出）。
- **约束引用**：`power-arch.md` 第 80 行"EN1 ... 直连 **VOUT**"、第 127 行"EN1 连接 | 直连 VOUT"。
- **影响**：功能上 3.3V 也是逻辑高，充电器仍按 EN2=0/EN1=1 走 USB500，问题不大；但确实偏离文档。
- **置信度**：中（明确偏离；影响低）。

### B7. ILIM 直接接 GND，文档要求 10kΩ → GND

- **网表**：`U3-12(ILIM) ∈ GND`（直连）。
- **约束引用**：`power-arch.md` 第 86 行"ILIM ... 10kΩ → GND（备用）"、第 128 行"ILIM 电阻 | 10kΩ → GND（备用）"。
- **影响**：EN2=0 时 ILIM 不生效，功能影响低。
- **置信度**：中。

### B8. 电池分压取自 P+（电池），文档要求取自 VOUT

- **网表**：`$1N210 = {U2-3(AIN), R9-2, R10-1}`，`R9-1 ∈ P+`（电池正极），`R10-2 ∈ GND`。
- **约束引用**：`power-arch.md` 第 130 行"分压电阻 100kΩ + 100kΩ ... **VOUT** → 100k → MCP3021 VIN → 100k → GND"；`software-notes.md` 第 45 行"插 USB 时 VOUT=4.4V"。
- **说明**：VOUT 与 P+ 在充电时经充电 IC 内部通路接近等电位，但空载/放电时不同；文档的例子（USB 时 4.4V）对不上"测 P+"。是文档与原理图的取向不一致。
- **置信度**：中（冲突明确，但取 P+ 测电量未必更差，属取向问题）。

## 五、附带：固件交叉核对中发现的疑点（与原理图无关，供参考）

- `input.c` 第 172-179 行 `input_arm_wakeup()` 配了 `pull_up_en = GPIO_PULLUP_ENABLE`（内部约 45k），而 `encoder-arch.md` 第 62 行要求的是外部 100kΩ 上拉。内部上拉与外部 100k 并联会把等效上拉降到约 31k，**改变分压比**，与 `input.c` 里按 100k 算出的阈值 `74/166/324/582/2000` 不一致。这属于固件问题（不是原理图问题），但会直接影响按键判读。
- `eink.c` 第 24 行 SPI 时钟 10MHz；`software-notes.md` 第 93 行建议"2~4MHz"。属固件/文档不一致。
- `input.c` 第 180-182 行用 `gpio_wakeup_enable` + `esp_sleep_enable_gpio_wakeup()`（GPIO 唤醒），`encoder-arch.md` 第 141 行、`变更-固件阶段二.md` 第 113 行写的是 `EXT1`。C3 实际没有 EXT1，固件写法应是对的，属文档过期。

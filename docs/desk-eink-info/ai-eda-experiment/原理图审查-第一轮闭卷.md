# 原理图审查（第一轮，闭卷）

> 对象：`bord/桌面小摆件.eprj2` 的原理图（当前工程内有两个原理图：`v2` 与 `v1-验证板`）。
> 方式：把工程**复制**成 `review-target.eprj2`，在立创EDA里打开副本，用 API 导出网表（Protel2）与引脚表，再做拓扑级比对。
> 约束：拿不到设计约束、数据手册，不能联网；**只报客观错误，不评论设计选择**。
> 结果：原工程未被改动（`bord/桌面小摆件.eprj2` 的 sha256 与审查前一致，`EBAA715E...`）。副本 `review-target.eprj2` 被编辑器重写过，属正常。

## 结论概述

共 6 条客观问题（外加 1 条低置信度、需确认的供电域问题）。最要紧的是 **C6 串在 USB VBUS 与充电 IC 输入之间，导致充电器没有直流输入**；其次是 **充电指示 LED 看不到导通回路** 和 **4 个只连了一个点的网络**。

## 审查依据（数据）

- 网表：`netlist-v2-Protel2.txt`（v2，48 器件 / 47 网络）、`netlist-v1验证板-Protel2.txt`（v1，45 器件 / 42 网络）。
- 引脚表：通过 API `getAllPinsByPrimitiveId` 枚举全部器件引脚（含 `noConnected` 标记）。
- 两个原理图的网表互为对照（v1 是验证板，v2 是当前版本）。

坐标说明：下面括号里的坐标是原理图画布坐标，单位 0.01 inch，方便在画布上定位。

---

## 1.（高）C6 串接在 USB VBUS 与充电 IC 输入之间，充电输入没有直流回路

- **位置**：充电 IC U3（BQ24073，画布约 785,640）的 IN 脚（U3-13）；电容 C6（1uF，约 705,710）。
- **证据**（网表原文）：
  ```
  ( $1N171
    U3-13 BQ24073RGTR-IN Passive
    C6-2 CAP_0603-2 Input )
  ( VBUS+
    USB1-A4 TYPE-C-VBUS
    USB1-A9 TYPE-C-VBUS
    C6-1 CAP_0603-1 Input
    C7-2 CAP_0603-2 Input
    U2-1 MCP3021A5T-E/OT-VDD )
  ```
  C6 一脚在 `VBUS+`、另一脚在 `U3-13`，两个网络之间**只有 C6 这一条路径**。
- **为什么是问题**：电容隔直。USB 的 5V 直流到不了 U3-13（IN），充电器没有输入电源，插上 USB 也充不了电。正常应是 VBUS 直接连 IN，C6 作为 IN 对地去耦（改成 IN-GND）。
- **置信度**：高。
- **旁证**：v1-验证板里同样如此，是稳定复制下来的接法，不是偶发。
- **建议核对**：在画布上确认 VBUS 与 IN 之间是否真的只有一颗电容，是否漏画了直连线。

## 2.（中）充电指示 LED1 看不到导通回路

- **位置**：LED1（GL0603UR01，约 705,590）、限流电阻 R3（10K，约 665,590）、U3-9（CHG#）。
- **证据**：
  ```
  ( $1N158  LED1-1 GL0603UR01-A  R3-2 )
  ( $1N157  U3-9 BQ24073RGTR-CHG#  LED1-2 GL0603UR01-C )
  GND 里包含 R3-1
  ```
  即：LED 阳极（A）经 R3 接 **GND**，阴极（C）接 CHG#。
- **为什么是问题**：阳极在 GND（最低电位），阴极接 CHG#。无论 CHG# 是高还是低（低有效时被拉低），阳极都不高于阴极，LED 不会正向导通，指示灯不会亮。正常应是阳极经限流电阻接正电源、阴极接 CHG#。看起来是 LED 反接，或 R3 应该接正电源（如 P+ / 3V3 / 3.0V-4.2V）而不是 GND。
- **置信度**：中（"阳极在 GND"是客观事实；CHG# 为开漏/低有效是常见做法，但没有数据手册逐条确认）。
- **旁证**：v1 同样。

## 3.（中）四个网络只连了一个点：GDR / RESE / TSCL / TSDA

- **位置**：FPC1（显示连接器，约 245,710）的 2、3、6、7 脚。
- **证据**：网表里这 4 个网络各只有 1 个引脚：
  ```
  GDR  : ["FPC1-2"]
  RESE : ["FPC1-3"]
  TSCL : ["FPC1-6"]
  TSDA : ["FPC1-7"]
  ```
- **为什么是问题**：单点网络在电气上不构成回路。若这些信号本该由 MCU 驱动/读取（RESE 像复位、TSCL/TSDA 像触摸 I2C、GDR 不明），就是漏接。若设计上它们只到连接器、由显示模组内部处理，就不算错。仅凭网表无法判断意图。
- **置信度**：中（"只连了一个点"是客观事实，置信度高；"是错误"取决于设计意图，置信度中）。
- **旁证**：v1 同样。

## 4.（中）U4（DS3231 RTC）的 VBAT 没有电源，只挂了一颗电容

- **位置**：U4-6（VBAT，U4 约 305,385）；C8（10uF，约 225,370）。
- **证据**：
  ```
  ( $1N187  U4-6 DS3231MZ+TRL-VBAT  C8-2 )
  GND 里包含 C8-1
  ```
  该网络只有 VBAT 脚和一颗电容，没有电池、没有 3V3、没有其它源。
- **为什么是问题**：RTC 的备电脚悬空只挂一颗电容，起不到备电作用。若不用备电，通常应把 VBAT 接到 GND，而不是悬空并加一颗电容。
- **置信度**：中。

## 5.（中）3V3 电源轨只有一颗 1uF 去耦

- **位置**：`3V3` 网络。
- **证据**：`3V3` 共 15 个节点，含 U1（ESP32-C3）的 3V3、U4（DS3231）的 VCC、U7（蓝牙模组）的 VDD、U5（LDO）的 VOUT、U3 的 EN1、FPC1 的 8/15/16 脚；网络里**唯一的电容是 C12（1uF）**。
- **为什么是问题**：三颗 IC 的电源脚共用一颗 1uF，网表里看不到每颗 IC 各自的 0.1uF 高频去耦。属于"去耦缺失"这一类。
- **置信度**：中（"只有一颗电容"是客观事实；"不够"是工程判断，没有数据手册逐颗核对）。

## 6.（低）FPC1 符号 26 脚，封装名写 24P

- **位置**：FPC1，符号 `FPC-05F-24PH20`，封装 `FPC-SMD_24P-P0.50_FPC-05F-24PH20`。
- **证据**：引脚枚举显示 FPC1 有 1 到 26 脚；1、4、19 标记为 NC；25、26 接在 GND。封装名写 24P。
- **为什么是问题**：若封装实际只有 24 个焊盘，25、26 脚（GND）就没有焊盘可落，GND 连接会丢失。也可能封装是 24 信号 + 2 屏蔽焊盘共 26 个，那就没问题。
- **置信度**：低（本审查没能拿到封装的实际焊盘数，`lib_Footprint.get` 调用报错；只有封装名可作线索）。

## 附：一条低置信度、需确认的供电域问题

**U2（MCP3021 ADC，约 805,800）由 USB VBUS 供电**：`VBUS+` = USB1-A4/A9 + C6-1 + C7-2 + **U2-1（VDD）**。而它的 I2C 挂在 3V3 上拉的 `GPIO18/GPIO19` 上，输入经 R9/R10 分压测电池（P+）。电池供电（无 USB）时该 ADC 无电，"用电池供电时测不了电池"，且其 I2C 被 3V3 上拉。这可能是有意为之，不属于本轮的"客观错误"，仅作提示，置信度低。

---

## 检查过、本轮未发现异常的项

- USB Type-C 受电端 CC 端接：CC1（A5）经 R8（5.1K）到 GND，CC2（B5）经 R2（5.1K）到 GND，符合受电端做法。
- I2C 上拉：`GPIO18`（SCL）有 R7（10K）上拉到 3V3，`GPIO19`（SDA）有 R6（10K）上拉到 3V3。
- 各 IC 的电源/地脚都有连接：U1（3V3/GND/EP）、U2（VDD/VSS）、U3（VSS/EP 等）、U4（VCC/GND）、U5（VIN/VOUT/VSS）、U7（VDD/GND）、U8（7/8 到 GND）。
- 除 C6 外，每颗电容都有一脚接 GND（都是对地去耦/储能）。
- 每个电阻两端都有网络，没有单脚悬空的电阻。
- 除图框（sheet / drawing-symbol_a4）外，没有其它悬空的非 NC 引脚。
- 单节点网络只有 GDR/RESE/TSCL/TSDA 四个（见第 3 条）。

## 本轮没做的事（按约束）

- 不判断引脚功能分配是否合理、参数取值是否合适、电源域/上拉阻值等设计选择（除上面明确指出的客观错误）。
- 不做器件选型、工艺、封装与引脚编号一致性之外的判断。
- 没有数据手册，所以凡是依赖器件具体行为的地方（如 CHG# 的开漏/极性、MCP3021 的电平门限、BQ24073 各配置脚）都标注了置信度，未当作定论。
